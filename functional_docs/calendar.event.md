**Summary:**

<!-- SUMMARY:model:calendar.event -->
This repo adds three record rules on Calendar Events: internal users may access all events, portal users only events where they are an attendee, and a global rule limits write, create and delete on private events to their attendees. No fields, views or actions are added.
<!-- /SUMMARY -->

**Record rules (3):**

| Name | Record name | Function | Depends on | Used by |
|---|---|---|---|---|
| All Calendar Event for employees | `rule_all_calendar_event_for_employees` | For User types / Internal User: read/write/create/delete on Calendar Event with no record filter (empty domain = all records). | `group base.group_user` (base)<br>`model calendar.event` (calendar) |  |
| Own events | `rule_own_events` | For User types / Portal: read/write/create/delete on Calendar Event only where `[('partner_ids', 'in', user.partner_id.id)]`. | `calendar.event.partner_ids` (calendar)<br>`group base.group_portal` (base)<br>`model calendar.event` (calendar) |  |
| Private events | `rule_private_events` | For everyone (global rule): write/create/delete on Calendar Event only where `['|', ('privacy', '!=', 'private'), '&', ('privacy', '=', 'private'), ('partner_ids', 'in', user.partner_id.id)]`. | `calendar.event.partner_ids` (calendar)<br>`calendar.event.privacy` (calendar)<br>`model calendar.event` (calendar) |  |
